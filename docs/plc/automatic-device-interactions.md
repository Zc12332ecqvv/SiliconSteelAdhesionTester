# PC自动设备交互

PC不负责机器人取放料或工位流转，只响应PLC在自动流程中给出的允许信号。

## 已实现握手

| 交互 | PLC→PC允许 | PC→PLC完成 | PC→PLC结果 |
|---|---|---|---|
| S2取向二维码 | `DB4120.DBX578.3` | `DB4120.DBX576.3` | OK `.4` / NG `.5` |
| S2第一次拍照 | `DB4120.DBX579.0` | `DB4120.DBX577.0` | 无结果位 |
| S2第二次拍照 | `DB4120.DBX578.0` | `DB4120.DBX576.0` | OK `.1` / NG `.2` |
| S3无取向二维码 | `DB4120.DBX844.3` | `DB4120.DBX842.3` | OK `.4` / NG `.5` |
| S4无取向拍照 | `DB4120.DBX1110.0` | `DB4120.DBX1108.0` | OK `.1` / NG `.2` |

应答位保持到PLC撤销对应允许位，然后PC将完成/OK/NG复位为0。每个允许周期只执行一次设备操作。

## SR-1000

当前实现为PC作为TCP客户端连接SR-1000。连接后可发送可配置的触发命令和结束符，并等待一条二维码结果。取向与无取向读取器可以分别配置IP和端口。

## 相机临时适配方式

在相机SDK未提供前，程序采用文件落盘接口，并在每次PLC拍照请求时创建一个 `.trigger` 请求文件：

```text
CameraInput/
  requests/
  oriented/before/
  oriented/after/
  non-oriented/tape/
```

相机或视觉软件收到请求后，将新图片写入对应目录。程序确认文件大小稳定后归档原图、执行OpenCV判定并返回PLC结果。

## 追溯与异常

- 取向和无取向二维码分别进入FIFO队列。
- S2两次图片使用同一个取向二维码，S4图片使用最早尚未完成的无取向二维码。
- 没有二维码时禁止生成无追溯视觉记录。
- 二维码、原图、视觉结果、操作和故障均写入SQLite。
- 第一次拍照没有NG位，失败时不返回完成，只记录故障并等待PLC撤销/重试。
